# LinkMind 项目级 Agent Studio：产品与实现设计

状态：产品设计与分阶段实施说明，2026-11-13。0.5.0 实现第一批：稳定本地项目身份、三类目标、工作依赖、决定与证据、人工验收、修订记录、跨会话运行访问及 MCP 接续工具。后台执行、事件续作、预算执行、自动验收和跨设备项目文件仍是后续设计。下文描述完整目标架构，不能全部视为已交付；实际使用以 README 为准。最初设计依据为 0.4.0 的 `9c0bf5a`。复现、优化、开发是用户指定的三类项目目标；保持 DSH 原生工作区与会话体验。

## 1. 产品对象从运行提升为项目

产品承诺：用户交给 LinkMind 一个具身项目目标，Studio 持续组织所需的阅读、准备、实验、修改和验证，直到交付约定成果，或明确说明为什么无法完成。

项目具有稳定身份，不随会话结束而消失。会话用于沟通和执行开发工作，运行是项目活动的一种；一次模型回复结束、一次程序退出或一个待办打勾，都不表示项目目标已经达成。

项目必须随时回答：

- 我们要交付什么，怎样算达到目标？
- 现在依据哪些版本、环境、约束和预算推进？
- 已经得到哪些可核验结论，哪些仍是假设？
- 当前有什么在执行、因什么受阻、接下来准备做什么？
- 用户离开或应用重启以后，哪些工作仍在继续，哪些需要恢复？

## 2. 0.4.0 为何仍是任务级

`backend/src/roborag/studio/projects.py` 的项目登记主要保存目录、名称和单个 `session_id`；`open_workspace` 按目录与会话一起查找登记。相同目录在另一会话中可能成为另一条项目登记。这个行为是现有会话隔离的一部分，不能简单删除检查来实现共享。

现有运行记录保存启动配置、源码线索、日志与结果，但没有持续的项目目标、验收标准、里程碑、决策记录和待处理事件。`compare` 主要比较两份原始记录，不能判定项目目标达成。

`runtime.mjs` 和 `service.py` 把服务与子进程的生命周期绑定到桌面宿主。当前应用退出会停止其拥有的运行。把进程放入后台，或仅新增一个定时器，不能直接得到可靠的项目续作。

这些能力保留为运行层；在其上增加项目层，并调整身份、权限和生命周期。

## 3. 三类目标：不同推进方式与交付标准

新建项目时可以选择主要目标；一个长期项目可以顺序或并列拥有多个目标，例如先复现原版，再派生一个优化目标。每个目标保存自己的类型、版本、预算、验收和结论。不能用切换下拉框的方式覆盖上一目标的历史。

### 复现：建立可信的原版结果

- **输入**：来源仓库与提交、原始模型/权重、环境和资产版本、任务范围、运行协议、预期结果及允许差异、资源预算。
- **推进**：核对来源 → 准备环境 → 小规模验证 → 按约定协议执行 → 对照证据 → 交付复现报告。流程允许回到准备或核对阶段，不强制固定的计划步骤。
- **Agent 的职责**：保留原版，识别缺失条件，记录每个兼容性修改，定位与原结果的差异；不能为了提高成绩偷偷切换策略、模型、布局或筛掉失败。
- **交付**：可再次运行的环境/配置说明、全部尝试索引、原始报告与画面、与目标的对照及差异解释。
- **目标判定**：复现达到约定范围／未达到／证据不足，明确区分。协议执行和报告交付完毕，可以关闭工作，但不能把“未达到”改写成“复现成功”。

### 优化：在固定约束下获得可验证的改进

- **输入**：可追溯的基线、要优化的指标、不得退化的约束、允许修改的范围、开发集与验证集、预算和停止条件。基线可以来自其他项目，不强迫用户先完成一个复现目标。
- **推进**：确认基线 → 诊断问题 → 提出改进假设 → 实现候选 → 在开发范围筛选 → 独立验证 → 接受或舍弃候选。
- **Agent 的职责**：记录每个候选为什么尝试、改动了什么、结果怎样；保留负结果；监测预算和回归。基线或评价口径变化时创建新修订并重新评估可比性。
- **交付**：候选代码与配置、与基线的可比证据、资源代价、适用范围和已知回归，或“在该预算内未找到可靠改进”的报告。
- **目标判定**：只在预先约定的改进阈值和约束均有证据支持时标记达成。一次更好或开发集成绩更高不是自动验收依据。

### 开发：交付一个可使用、可维护的具身能力

- **输入**：用户要解决的问题、目标使用者、支持的平台/机器人/仿真器、交付形态、使用场景、验收条件和范围。
- **推进**：澄清需求 → 设计与分解 → 实现与集成 → 场景验证 → 文档和交付；项目可包含多项功能、多个版本以及后续维护。
- **Agent 的职责**：连接需求、实现变更和验证证据，持续处理依赖、集成问题和回归；每个局部功能完成后重新检查总体交付。
- **交付**：可安装或可运行的成果、使用说明、版本和变更记录、场景验证、已知限制；发布目标按用户已有授权执行。
- **目标判定**：整套约定场景和交付要求满足后验收。代码提交成功、单个函数实现或单元测试通过均不能代替产品交付。

## 4. 共同的项目底座

### 持久项目与工作计划

项目保存稳定 `project_id`，关联 DSH workspace。第一版支持一个主工作区；数据模型允许以后附加其他仓库、计算节点和设备。会话是项目中的入口，不是项目的所有者。

每个目标包含可修改的里程碑和工作项。工作项可以是阅读、环境准备、实验、代码修改、数据处理、集成或交付，具有依赖、执行者、输出和验证条件。先支持单个项目 agent 顺序执行；多个 agent 不是项目级支持的前提。

计划是可修订的工作记录。用户调整需求或新证据推翻假设时，保留旧计划及改变原因，重新安排后续活动。依赖关系用于管理项目工作，不进入机器人策略内部充当强制阶段调度。

### 项目知识与证据

将以下信息保持可编辑、可追溯：用户约束与决定、已验证环境、已知问题、有效结论、失败尝试、待验证假设。每条重要结论关联来源、适用版本和时间；过期结论标记失效，而不是继续注入上下文。

项目知识是项目事实与决策记录，和机器人经验检索、skill、通用长时记忆分别处理。不把整段聊天反复塞进提示，也不把第三方 README 中的文字升级为用户授权。新会话获得当前目标、有效约束、最近证据和下一步摘要，必要时打开原始记录。

运行、代码修订、数据版本、报告、录像和交付物都通过 ID 关联到目标和工作项。原始证据保留；摘要可重建。数据不完整时显示缺口，禁止把缺失指标填零后当作实测结论。

### 项目推进循环

每次继续工作时：读取最新目标修订和用户指令 → 核对正在执行的工作、资源与证据 → 选择一个可执行工作项 → 在预算内行动 → 验证输出 → 保存事实与下一步 → 等待结果、继续或暂停。

唤醒来自用户消息、运行完成、资源就绪、检查点、外部任务状态变化，以及用户明确启用的时间计划。优先采用事件；没有新事实时不反复调用模型自我反思。

重复的同一错误触发有限诊断与阻塞记录，不无上限重试。运行结束仅更新对应工作项；Agent 还要根据目标验收决定后续行动。

## 5. 常驻能力的确切含义

必须分开交付：

1. **项目状态持久化**：关闭应用后目标、证据和计划仍存在；第一批实现。
2. **任务继续执行**：由独立 supervisor 管理的、已授权的模拟/计算作业可以在 UI 关闭后继续；后续实现，界面明确告知哪些作业会继续。
3. **Agent 后台续作**：作业完成后，在授权范围与剩余预算内继续后续工作；需可靠唤醒和执行控制。
4. **周期维护**：用户设置条件后检查依赖更新或回归；不是所有项目默认永久运行。

项目服务应与窗口解耦，负责任务状态、事件、执行租约和资源归属；模型只在需要判断与行动时被唤醒。DSH 继续负责会话、模型调用和原生工具。实施前核实 DSH 当前后台执行扩展点，优先复用；缺少持久、去重或取消语义时再补最小桥接。

每次执行具有 `project_id / objective_revision / work_item_id / attempt_id`。事件去重、执行租约和幂等启动避免重复模型调度或重复实验。启动后崩溃时先核对既有运行，无法判定的标为不确定，不能直接再启动一次。复用现有运行 receipt 与进程归属检查。

暂停项目：停止安排新工作，正在执行的工作按用户选择继续或终止；停止运行：终止指定执行，两者在 UI 上分开。用户暂停后，定时事件不能自动解除暂停。

恢复项目先检查最新代码/配置、既有进程、资源占用和剩余预算。不能仅靠旧摘要重放上一次动作。第一版保持单个活动运行，直到资源租约与隔离实现后再支持并发。实体设备的恢复必须符合设备适配器的连接、现场确认和停止条件；桌面进程停止不等于硬件急停。

## 6. 项目状态、预算与验收

项目/目标状态：草拟、可推进、推进中、等待资源、需要用户输入、已暂停、待验收、已关闭。运行状态单独管理，不用一个 `running` 字段表示所有情况。

目标结果另存为达成、未达成、证据不足或取消。工作完成、报告交付和科学结论是不同字段。验收连接每个条件与证据，由确定性检查提供可核验结果，agent 解释差异，按用户选择采用人工或预授权的自动验收。不能由 agent 自行降低标准来完成目标。

预算至少覆盖时间、运行次数、模型用量和计算资源；能获得可靠价格时才展示费用估计。失败与重试也计入消耗。用户可以授权“准备环境但不运行”“按协议执行整组”“在本预算内优化”等范围；已有授权继续有效，不逐项重复询问。预算耗尽暂停新工作并交付当前证据，不能冒充目标完成。

变更目标范围、实验协议、允许动作或预算时保存新修订，校验在途作业是否仍然有效。不能让旧排队事件执行新目标的未授权动作。撤销权限与暂停信息优先于任何旧计划或会话摘要。

## 7. 保留 DSH 的产品体验

左侧继续使用 DSH 工作区与会话列表。用户在工作区内建立项目目标，默认一次只需填写希望完成什么、来源或起点、主要约束；assistant 将其整理为可审阅的目标说明。复现/优化/开发作为目标类型，不新增三个聊天应用。

会话顶部显示当前项目与目标、状态、下一步或阻塞原因；侧栏增加项目概览：目标与验收、里程碑、正在进行的工作、证据/交付物、资源预算。现有配置、运行与摄像头仍作为可展开的详情。

用户回来时首先看到“上次停在哪里、期间有什么变化、下一步是什么”。不以一排空图表或新建任务按钮作为项目入口。长期目标下的新会话继承项目上下文，仍保留各自独立的话题和对话记录。

示例项目旅程（设计示例，不是新增实验结果）：

> 在工作区建立“复现 HexaShell Push-T”目标，约定来源、范围与协议。环境准备完成后按协议执行，用户离开时在授权范围内继续。返回后看到已完成和未完成的部分、失败证据与剩余预算。复现结论形成后，派生“降低模型调用开销”的优化目标，引用原基线而不改写历史；再派生“支持另一任务”的开发目标。三个目标共用项目知识，各自有交付与验收。

## 8. 实现边界与兼容迁移

- **身份与权限**：DSH 宿主从真实 workspace/session 上下文绑定项目，不能信任模型提供的 session ID。加入项目的会话获得明确作用域；控制运行仍需有效的执行租约。不要移除旧会话归属校验后开放所有项目。
- **项目文件**：建议 `linkmind.project.json` 保存可分享的目标描述与版本化配置，现有 `linkmind.studio.json` 继续负责启动配方。长日志、凭证、机器路径、调度状态和资源租约留在本机私有存储。
- **本机状态**：建议用 SQLite 事务保存项目索引、目标修订、工作项、决策/证据索引、事件及租约，避免多会话写入覆盖。大文件保留为独立资产。第一版不要求用户理解这些对象。
- **迁移**：保留现有登记和 run ID，通过映射关联到新 project ID。同一规范目录可能有多个合法目标；不同 checkout 即使远端相同也不能无条件合并。目录迁移提供显式重新定位。旧记录证据不足时保留原样并标记缺口。
- **MCP 与 UI**：先增加获取/修订目标、读取项目摘要、登记决策与证据、提出/更新工作项、暂停/继续等接口。现有 run 接口通过绑定关系写入项目记录。每次修改校验 revision，冲突返回并重新读取，不静默覆盖。
- **运行适配器**：声明准备、启动、观察、结果、停止及可选引导/恢复能力。没有恢复接口的外部策略不可标为可恢复；训练检查点、仿真状态恢复和聊天上下文恢复是三件不同的事。
- **职责**：项目 agent 负责整个目标的推进；原方案的执行 agent/策略继续执行任务。两者可以使用不同模型，运行配置不得被项目会话模型隐式替换。

## 9. 建设顺序与验收

### 第一批：项目可以跨会话延续

稳定身份、三个目标模板、目标与验收修订、项目摘要/决策/证据、工作项关联、原生项目概览。继续使用当前前台运行生命周期，明确关闭应用会终止当前执行。

验收：新会话打开同一项目，能接续原目标、看到旧证据和下一步；旧运行仍可查看；会话并发修订不会覆盖；不同项目相互隔离；复现、优化、开发各有一种从建立目标到证据验收的路径。一次 run 成功不能自动完成项目。

### 第二批：项目可以可靠地持续推进

独立 supervisor、资源租约、预算、运行完成事件、有限重试、暂停/恢复与前台/后台状态。先支持本地模拟/计算任务，后续接远端和设备。

验收：重启后无重复运行；作业完成后续作一次；用户暂停优先于排队事件；预算到限停止新动作；未知进程状态不冒险重放；用户离开期间的工作与结果可核对。

### 第三批：各类项目形成完整交付

复现的协议批次与差异报告、优化的候选/基线/验证管理、开发的需求到交付物关联；增加同步回放与项目导出。需要训练的项目通过现有框架适配数据、训练和检查点，不先重建训练平台。

验收：另一位用户能依据导出说明检查前提并运行支持的配置；不丢失失败或未完成尝试；缺失资产与不可比较条件被明确列出；交付报告可追溯到原始证据。

优先实施第一批中的持久项目身份与跨会话续作，随后实现有界的项目推进。经验系统、RSI、自动基础设施选择和装饰性推理可视化继续独立，不作为本次项目底座的前置条件。
