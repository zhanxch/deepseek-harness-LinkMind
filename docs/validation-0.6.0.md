# 0.6.0：原生 Goal 与共享任务验证

2026-11-13，Linux x64，DSH 0.2.2-rc.2。验证对象是工作台交互与任务持久化，不是控制算法或机器人评测。

## 设计变化

用户从 `/goal 复现|优化|开发 <要求>` 开始。插件复用 DSH 的 Goal 指令身份、续行、目标条、暂停和恢复，在工作区任务库中保留原始要求、模型完善的任务说明、必要步骤、决定、证据和关联对话。模型按实际任务安排步骤，不再预填固定四步或要求用户填表。

任务库是跨对话记录，原生 Goal 是当前执行会话的控制机制。每个任务只有一个执行会话；旧会话正在执行时拒绝接续，闲置旧 Goal 在转移时暂停。当前会话已有未完成目标时明确提示先收起。数据库比较修订和原生 Goal 修订，迟到状态不能覆盖新的所有者。原始指令保留，修改后的要求另行记录。

## 检查

- 独立包：25 项 Python 测试通过，覆盖原有运行、工作区、证据与新增三类任务、无表单创建、持久化、跨会话接续、旧会话拒写、过期状态拒绝、原生激活状态、原始指令保留和自动运行关联。
- 完整 LinkMind 集成：33 项 Studio 测试、7 项旧项目记录测试、6 项 Goal 任务测试和 13 项 Node 测试通过。未改动冻结实验、模型策略或原生报告。
- 实际 DSH：从斜杠菜单进入 Goal，创建复现任务、修改、暂停和跨对话接续；普通用户接口不能伪造原生 Goal 状态。
- UI：浅色、深色、960×720 的约束尺寸；空列表、类型筛选、加载、接续冲突、已暂停/待继续状态与原生任务条。外观测试使用隔离 profile，随后恢复跟随系统及窗口尺寸。

## 真实会话验证

使用本机 Codex 适配器执行一个明确限定的功能验证任务：完善已有任务说明、恰好两条验证标准和一个步骤，读回确认，登记结论并完成步骤；不运行机器人、修改源码或创建第二个任务。

模型实际写入并读回了任务说明、标准、步骤、验证结论。一次测试中途调整原生轮次限制，使旧轮次的完成调用被 DSH 拒绝；随后 GPT-6-Sol 返回容量繁忙，记录与进度仍完整保留，面板显示待继续。已有会话切换到 GPT-6-Astra 又触发实验 Codex 适配器的上下文压缩限制。

随后在新会话选择 GPT-6-Astra，接续同一个工作区任务，读取之前的说明和证据，并通过原生工具完成 Goal。任务库同步为已完成，保留两个关联对话，原任务没有复制。另一次在原会话仍执行时发起的接续请求被拒绝，原执行未被打断。

这些失败与恢复用于验证真实状态，不计为任务评测成绩。完成状态标明来自助手报告，实验结果仍应检查原始证据。

## 边界

共享任务目前限于同一台机器、同一个规范化工作区，没有跨设备同步、任务级统一计费预算或常驻后台执行。DSH 的轮次限制属于当前原生 Goal；跨会话接续会建立新的原生 Goal。暂停 Goal 不会停止已启动的外部程序。

Codex 适配器仍属实验功能，已有长会话切换模型可能因上下文压缩信息不完整而失败；可新建会话并接续同一任务。用户的默认模型、登录与原有会话保留。
